# FX 意思決定エンジン — 固定設計（完全版）

> **目的**: 予言機ではなく、条件付きで期待値を守る意思決定支援。  
> **正本**: 本ファイルの「固定」節だけを実装・検証の拘束条件とする。  
> **由来**: 前回エージェント（外為価格予測分析 / bc-019f6ab8-…）の目視Gate設計を流用し、ML用に再定義。

## 0. スコープ（固定）

### 対象ペア

| 段階 | ペア | 扱い |
|------|------|------|
| Phase A（必須） | USDJPY, EURUSD | 別スコア・別閾値。同時新規は禁止 |
| Phase B（慣れてから） | GBPUSD, EURJPY | 同一特徴量枠を移植。サイズは控えめから |

### 価格の正

- 学習・検証・本番判定は **同一ソースの BID（または提示レート）** で統一する。
- 混在（TV判定・別業者執行など）する場合も、**特徴量計算に使う足は1ソースに固定**する。

### 方針（前回からの継承）

- **トレンド主・レンジ従**（ADXで排他切替）
- 単指標禁止。帯域 × 過熱 × レジーム × ボラ
- パラメータ弄り禁止（下記の固定値以外は採用しない）
- 自動売買は本設計の範囲外。出力は確率・見送り・サイズ係数まで

### 非目標（明示的にやらない）

- 全ペア共通の単一高精度予測器
- 水準（価格そのもの）の高精度当て
- MACD / ストキャス / RCI / スーパーBB＋スパン同時盛り

## 1. 採用インジの最小セット（重複なし）【固定】

原則: **役割ごとに指標は1系統のみ**。価格から作る派生は「別表現の重複」になりやすいので、役割が被るものは入れない。

### 1.1 コア6系統

| ID | 役割 | 採用 | 固定パラメータ | 特徴量化（例） | 入れない同役割 |
|----|------|------|----------------|----------------|----------------|
| I1 | レジーム判定 | **ADX / DMI** | period **14** | `adx`, `plus_di`, `minus_di`, `di_spread` | 独自トレンド強度、複数ADX |
| I2 | ボラ尺度 | **ATR** | period **14** | `atr`, `atr_pct=atr/close` | 別period ATR、ヒストリカルボラの併用は後述の実現ボラのみ可 |
| I3 | 帯域／位置 | **Bollinger** | **20, 2σ**（内帯1σは補助特徴のみ） | `%b`, `bb_width`, 外帯タッチフラグ | ケルトナー・ドンチャン（帯の重複） |
| I4 | 過熱／余地 | **RSI** | **14** | `rsi`, 30/70（日足は25/75も閾値候補だが学習特徴は生値） | ストキャス、RCI、CCI |
| I5 | トレンド床 | **EMA** | **20 / 50 / 200**（プラットフォーム上限なら200→180可） | 価格との乖離、整列フラグ `ema20>ema50>ema200` | SMA群、MACD（EMA差分の重複） |
| I6 | 構造／拒否権 | **一目均衡表** | **9 / 26 / 52**（遅行・スパン定義は標準） | 雲上下、雲厚み、転換・基準の位置関係 | スパンモデル併用、スーパーボリンジャー併用 |

### 1.2 レジーム閾値（固定）

| ADX | モード | 新規 |
|-----|--------|------|
| **&lt; 20** | レンジ | レンジ系ラベル／戦略のみ |
| **20 – 25** | 中立 | **新規なし（見送り）** |
| **≥ 25** | トレンド | トレンド系のみ |

- 同一ペアでレンジとトレンドの同時新規は禁止。
- 一目は **拒否権／許可証**（学術本命ではない）。Gate衝突時は **ADX × BB × RSI を優先**し、一目は「雲と逆方向の新規を落とす」用途に限る。

### 1.3 時間フィルタ（指標ではないが必須特徴）

前回の実務知見を特徴として固定する（インジではないが重複しない情報）。

| ペア | 優先セッション（目安 JST） | 備考 |
|------|---------------------------|------|
| EURUSD | 16:00–24:00 | ロンドン〜NY前半 |
| USDJPY | 上記＋東京時間の扱いを別フラグ | 介入・指標は後段の外生で拡張可 |
| 共通 | 指標前後N分は `event_window` フラグ | Phase Aでは「時間帯ダミー」までで可 |

### 1.4 明示的に採用しないもの

- MACD, Stochastic, RCI, Williams %R, CCI（I4と重複）
- 複数の移動平均ファミリー同時（I5と重複）
- ケルトナー／ドンチャン（I3と重複）
- スーパーBB＋スパンの同時盛り（I3/I6と衝突しやすい）
- パラメータ探索（BB21, RSI7 等）— カーブフィットとして却下

### 1.5 特徴量の重複抑制ルール

1. 生のOHLC＋上記I1–I6から作る
2. 同一足で「相関が恒常的に高い派生」は片方落とす（例: BB幅とATR%がほぼ同型なら、帯域は`%b`、ボラは`atr_pct`に役割分担）
3. **実現ボラ**（直近n本のlog return標準偏差）はATRと近いが、ATRは真のレンジ、実現ボラは終値経路なので **どちらか一方を主、他方は副特徴1個まで**
4. 上位足の値は「その足の確定足のみ」を下位に接合（先読み禁止）

## 2. 時間足ごとの役割分担【固定】

対象足: **30分 / 1時間 / 4時間 / 6時間 / 12時間 / 1日**  
（前回のM15/M10単独戦略化禁止は維持。週足は日足の上位確認として任意追加可だが、Phase Aの必須入力ではない。）

### 2.1 役割マップ

| 足 | 役割名 | やること | やらないこと |
|----|--------|----------|--------------|
| **1D** | 戦略レジーム | トレンド/レンジの主判定、EMA整列、雲の上下、週次〜数日の方針 | エントリータイミングの微調整 |
| **12H** | スイング構造 | 日足と4Hの橋渡し。日足レジームの安定確認、押し目の大枠 | スキャル判断 |
| **6H** | 中期モメンタム | DI方向の持続、BB幅の収縮/拡大の確認 | 単独エントリー根拠 |
| **4H** | 戦術レジーム | H1の上位確認（前回「H1の上位＝日足」を実務向けに分解した層）。押し目Aの許可 | ノイズ追従 |
| **1H** | 主戦場（デイトレ） | ラベル生成の主ホライズン、Gate判定の主足 | 日足方針と矛盾する逆張り新規 |
| **30M** | 執行微調整 | 1H Gate通過後の入り位置・見送り最終判定 | 単独のレジーム判定・単独戦略 |

### 2.2 階層ルール（固定）

```
1D が方針（Regime Source）
  └─ 12H / 6H が方針の安定度（Consistency）
       └─ 4H が戦術許可（Tactical Permit）
            └─ 1H が主判定（Primary Decision）
                 └─ 30M が執行（Execution Timing）
```

1. **上位確定足のみ参照**（例: 1Hバー確定時点で見える最新の確定4H/6H/12H/1D）
2. 上位が中立（ADX 20–25）なら下位の強いシグナルも **見送り**
3. 上位トレンドに逆らう下位レンジ逆張りは Phase Aでは **禁止**
4. 30Mは「1Hが許可した方向」以外に使わない

### 2.3 足ごとのインジ使用

全足で同じI1–I6を計算してよいが、**意思決定に使う役割は足で変える**。

| インジ | 1D | 12H | 6H | 4H | 1H | 30M |
|--------|----|-----|----|----|----|-----|
| ADX/DMI | 主レジーム | 安定確認 | 持続確認 | 戦術レジーム | 主Gate | 参考のみ |
| ATR | 日次リスク | スイングSL目安 | — | 戦術SL | ラベル閾値・SL | 執行SL |
| BB | 位置の大枠 | 幅の状態 | 幅の状態 | 許可 | 主Gate | タッチ確認 |
| RSI | 日足過熱 | — | — | 過熱フィルタ | 主Gate | 最終過熱 |
| EMA | 整列（必須） | 整列確認 | — | 押し目床 | 押し目A | 微調整 |
| 一目 | 拒否権 | 雲厚 | — | 拒否権 | 拒否権 | 使わない |

### 2.4 主戦場の優先度（検証リソース配分）

1. **1H**（デイトレ主戦場）← 最優先でラベル・WF
2. **1D**（スイング方針・コスト耐性）
3. **30M**（1H条件付きのみ）
4. 4H/6H/12H は特徴量・フィルタ。単独の売買ラベルは Phase Aでは作らない

## 3. 正解ラベルとウォークフォワード手順【固定】

### 3.1 設計思想

- ラベルは「次足が上がるか」ではなく、**前回のGate思想を定量化したもの**
- 主出力は **方向確率ではなく、行動クラス＋有利度**
- コスト（スプレッド）込みで正とする

### 3.2 シンボル定義

- 主足バー `t`（主に1H）の終値確定時点で特徴量 `X_t` を確定
- 前方のみでラベルを定義（リーク禁止）
- `ATR_t` = 主足ATR(14) at `t`
- スプレッドコスト `c` = 検証対象業者の典型スプレッド（ペア別定数）。往復で差し引く

### 3.3 レジームラベル（先に付与）

主足ではなく **1D確定ADX** を優先ソースとし、なければ主足ADX。

| `regime_t` | 条件 |
|------------|------|
| `trend` | ADX ≥ 25 |
| `range` | ADX &lt; 20 |
| `neutral` | それ以外 → **学習上は常に `skip` 行動** |

### 3.4 行動ラベル（主タスク）【固定】

3クラス分類（または等価な2段階: skip vs trade → direction）

| `y_action` | 意味 | 付与条件の概要 |
|------------|------|----------------|
| `skip` | 見送り | neutral、または下記の long/short 条件を満たさない、または上位拒否 |
| `long` | 買い候補 | トレンドまたはレンジのロング認定が成立し、前方パスがコスト後に成功 |
| `short` | 売り候補 | 同上（売り） |

> 重要: 「シグナルが出た」だけでは long/short にしない。**Triple-Barrier で前方成功したものだけを正例**にする（認定装置のML化）。

### 3.5 Triple-Barrier パラメータ【固定】

主戦場 **1H** の固定値。日足用は併記。

#### A) トレンド押し目（本命）

| 項目 | 1H | 1D |
|------|----|----|
| エントリー前提（特徴側） | ADX≥25、DI方向一致、EMA整列、押し目（EMA20近傍またはBB中帯付近）、一目が逆方向なら除外 | 同型 |
| 利確バリア | `+1.5 × ATR` | `+1.5 × ATR` |
| 損切バリア | `-1.0 × ATR` | `-1.0 × ATR` |
| 時間バリア | **12本**（12時間） | **8本**（8営業日） |
| 成功定義 `long/short` | 利確バリアに**先に**到達（スプレッド `c` 控除後） | 同 |
| 失敗 | 損切先到達、または時間切れでコスト後リターン≤0 | 同 |
| 失敗時の行動ラベル | `skip` に落とす（無理に逆ラベルにしない） | 同 |

#### B) レンジ逆張り（従）

| 項目 | 1H | 1D |
|------|----|----|
| エントリー前提 | ADX&lt;20、2σタッチ後に帯内方向へ戻る、RSI極端、上位がrange | 同型（RSI 25/75可） |
| 利確バリア | 中帯（BB basis）到達相当 = 可変、下限 `+0.8×ATR` | 同 |
| 損切バリア | `-0.5 × ATR`（前回M30緩衝に近い保守） | `-0.3 × ATR` |
| 時間バリア | **8本** | **6本** |
| 成功/失敗 | トレンドと同様（先到達） | 同 |

#### C) 30Mラベル

- 単独では作らない。
- 1Hで `long/short` のときのみ、直後の30Mで「より良い入り」を回帰補助タスクにできる（Phase A必須ではない）。

### 3.6 補助ターゲット（任意、本線ではない）

| 名前 | 定義 | 用途 |
|------|------|------|
| `fwd_ret_net` | 時間バリア到達時のコスト後リターン | 期待値キャリブレーション |
| `hit_tp` | 利確先到達か | 診断 |
| `p_useful` | 取引すべき確率（skip vs not） | サイズ係数 |

### 3.7 モデル出力（固定）

1. `P(skip), P(long), P(short)`（合計1）
2. `size_mult ∈ {0, 0.5, 1.0}`  
   - `P(skip)` 高い → 0  
   - 中立帯 → 0.5  
   - 明確 → 1.0  
3. 最終アクションは `argmax` ではなく、**閾値τをWFで選ぶ**（過自信防止）

### 3.8 ウォークフォワード手順【固定】

#### データ期間

- 可能な限り長期間（目安10年以上）。不足なら「短いが厳密」を優先し、主張を弱める。
- ペア別に同じ切年を使う。

#### 分割（purlged walk-forward）

```
|---- Train ----|-- Embargo --|---- Test ----|
                 ↑ purge: ラベル時間バリア分をTrain末尾から削除
```

| 項目 | 固定値 |
|------|--------|
| Train | **24ヶ月** |
| Test | **6ヶ月** |
| Step | **3ヶ月** 前進 |
| Embargo | 主足で **最大時間バリア本数**（1Hなら12本）以上 |
| Purge | Train末尾から、ラベルがTestに食い込むサンプルを削除 |
| 最低Fold数 | **8**（満たなければ「検証不足」と明記し本番閾値を上げる） |

#### リーク防止チェックリスト

- [ ] 上位足は確定足のみ
- [ ] 一目の遅行スパンを未来値として使っていない
- [ ] 標準化はTrain内統計のみ
- [ ] 特徴選択・閾値τもTrain（または内側CV）のみ
- [ ] Testは評価専用（再学習の教師に使わない）

#### 内側検証

各Train内で時系列CV（n_splits=3程度）し、ハイパーパラメータは **最小構成のみ**:

- 木モデル深さ、学習率、クラス重み
- 行動閾値 τ

インジ期間（20/14/9/26/52）は **探索禁止**。

#### 評価指標（合否はこの順）

1. **コスト後期待値**（トレードした局面のみ、かつ全体の別掲）
2. **最大ドローダウン**
3. **取引頻度**（少なすぎ/多すぎの両拒否）
4. **確率キャリブレーション**（言った60%が概ね60%）
5. 的中率は参考指標（単独の最適化禁止）

#### 合格ライン（Phase Aの運用開始条件）

全条件を満たすこと。

| 条件 | 内容 |
|------|------|
| G1 | USDJPY と EURUSD の**両方**で、過半数Foldがコスト後期待値 &gt; 0 |
| G2 | どの単一FoldのDDも、事前に決めた口座リスク上限を超えない |
| G3 | `neutral` 強制skipを外した Ablation より、期待値またはDDが改善 |
| G4 | 指標パラメータを動かさなくても成立（動かして初めて良い結果は不合格） |
| G5 | Phase BペアはG1–G4を満たしてから移植。最初から合同学習しない |

#### ベンチマーク（必須比較）

- ランダム（コスト後）
- 常にスキップ
- 前回ルールの機械的Gate（MLなし）
- 単純Buy&Hold（参考）

MLが「機械的Gate」を安定して上回らない場合、**Gate規則のまま運用しMLは見送り推奨のみ**に降格する。

### 3.9 再学習と劣化監視【固定】

| 項目 | 値 |
|------|----|
| 再学習 | 3ヶ月ごと（WFのstepに合わせる） |
| 監視窓 | 直近3ヶ月のコスト後期待値・DD・頻度 |
| 自動停止 | 監視窓で期待値&lt;0 が継続、またはDD上限超過 |
| 変更管理 | インジ追加は「役割が空きがある」場合のみ。空きがなければ置換 |

## 4. 実装順序（本設計の消化手順）

1. データ: USDJPY/EURUSD の 30M基底から 1H/4H/6H/12H/1D をリサンプル（境界ルールを文書化）
2. I1–I6 計算＋上位足接合（確定足のみ）
3. regime + Triple-Barrier ラベル生成
4. ベースラインGate（MLなし）バックテスト
5. ML（skip/long/short）＋WF
6. G1–G5 判定
7. 合格後のみ GBPUSD / EURJPY へ移植
